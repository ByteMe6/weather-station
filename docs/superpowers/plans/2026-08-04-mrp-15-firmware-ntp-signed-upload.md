# MRP-15 — NTP sync + signed HTTPS upload loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Once the device is on WiFi, average BMP280 samples over a 5-minute window, sign the payload with the flashed device secret, and POST it to the backend over verified HTTPS — retrying transient failures up to 3 attempts and then dropping the reading.

**Architecture:** All logic that can be tested without hardware moves into two header-only `lib/` modules (`aggregate`, `upload`) covered by host-native Unity tests, following the existing `lib/reading`, `lib/wifi_state`, `lib/ota_state` pattern. `src/main.cpp` keeps only I/O: an upload sub-state machine inside the existing `STATION_CONNECTED` phase, the HTTPS client, and NVS-backed endpoint configuration. The backend change is limited to making `readings.humidity` nullable, because the BMP280 cannot measure it.

**Tech Stack:** PlatformIO + Arduino ESP32 core 2.0.17, ArduinoJson 7.4.2, rweather/Crypto 0.4.0 (`SHA256` with HMAC), `WiFiClientSecure` + `HTTPClient`, Unity (native tests), Supabase/Postgres migration + zod on the web side.

**Design spec:** `docs/superpowers/specs/2026-08-04-mrp-15-firmware-ntp-signed-upload-design.md`

// A reset that clears count but leaks a sum would still return false from
// accumulatorMean here, so prove it by averaging fresh samples afterwards:
// a leaked sum shows up immediately in the mean.
void reset_clears_previous_window(void) {
  SampleAccumulator a;
  accumulatorReset(a);
  accumulatorAdd(a, 30.0f, 900.0f);

  accumulatorReset(a);
  TEST_ASSERT_EQUAL_UINT32(0, a.count);

  float t = 0.0f;
  float p = 0.0f;
  TEST_ASSERT_FALSE(accumulatorMean(a, t, p));

  accumulatorAdd(a, 10.0f, 1000.0f);
  TEST_ASSERT_TRUE(accumulatorMean(a, t, p));
  TEST_ASSERT_FLOAT_WITHIN(0.001f, 10.0f, t);
  TEST_ASSERT_FLOAT_WITHIN(0.001f, 1000.0f, p);
}

// Same constant added 150 times sums exactly even in float, so vary the
// samples - otherwise narrowing the sums back to float would pass unnoticed.
//
// The regression check is on the raw sums, not the /150 mean: dividing by
// 150 shrinks a float sum's rounding error to a couple of float ULPs at the
// mean's magnitude (~1e-4), which is indistinguishable from ordinary
// compiler/platform rounding noise and made this test pass even with the
// sums narrowed to float. The undivided sum carries the full error
// (empirically ~0.006 hPa here) with a wide, stable margin over the ~0
// double-precision baseline. Unity's double asserts are compiled out on
// this platform (UNITY_INCLUDE_DOUBLE is off), so the comparison is done by
// hand rather than through TEST_ASSERT_DOUBLE_WITHIN.
void full_window_does_not_drift(void) {
  SampleAccumulator a;
  accumulatorReset(a);

  double expectedTemperatureSum = 0.0;
  double expectedPressureSum = 0.0;
  for (int i = 0; i < 150; i++) {
    float temperature = 21.7f + 0.013f * i;
    float pressure = 1013.25f + 0.017f * i;
    accumulatorAdd(a, temperature, pressure);
    expectedTemperatureSum += temperature;
    expectedPressureSum += pressure;
  }

  TEST_ASSERT_EQUAL_UINT32(150, a.count);
  TEST_ASSERT_TRUE(fabs(a.temperatureSum - expectedTemperatureSum) < 0.0001);
  TEST_ASSERT_TRUE(fabs(a.pressureSum - expectedPressureSum) < 0.0001);

  float t = 0.0f;
  float p = 0.0f;
  TEST_ASSERT_TRUE(accumulatorMean(a, t, p));
  TEST_ASSERT_FLOAT_WITHIN(0.001f, (float)(expectedTemperatureSum / 150.0), t);
  TEST_ASSERT_FLOAT_WITHIN(0.001f, (float)(expectedPressureSum / 150.0), p);
}

  SampleAccumulator a;
  accumulatorReset(a);
  accumulatorAdd(a, -10.0f, 1000.0f);
  accumulatorAdd(a, 10.0f, 1000.0f);

  float t = 0.0f;
  float p = 0.0f;
  TEST_ASSERT_TRUE(accumulatorMean(a, t, p));
  TEST_ASSERT_FLOAT_WITHIN(0.001f, 0.0f, t);

#pragma once
#include <stdint.h>

// One upload window's worth of sensor samples. The sums are double because a
// five-minute window holds 150 samples at the 2 s read interval, and a float
// sum of 150 pressure readings loses the last decimal we actually report.
struct SampleAccumulator {
  uint32_t count;
  double temperatureSum;
  double pressureSum;
};

inline void accumulatorReset(SampleAccumulator &a) {
  a.count = 0;
  a.temperatureSum = 0.0;
  a.pressureSum = 0.0;
}

inline void accumulatorAdd(SampleAccumulator &a, float temperature, float pressure) {
  a.count++;
  a.temperatureSum += temperature;
  a.pressureSum += pressure;
}

// False when the window collected nothing. The caller must skip the upload
// entirely rather than send a zero, which would be indistinguishable from a
// real reading once it is in the database.
inline bool accumulatorMean(const SampleAccumulator &a, float &temperature,
                            float &pressure) {
  if (a.count == 0) return false;
  temperature = (float)(a.temperatureSum / a.count);
  pressure = (float)(a.pressureSum / a.count);
  return true;
}
```

#pragma once
#include <stdint.h>
#include <stddef.h>
#include <stdio.h>
#include <string.h>
#include <math.h>
#include <time.h>
#include <ArduinoJson.h>

// "2026-08-04T12:00:00Z" - 20 characters plus a terminator, so outLen must be
// at least 21. zod's .datetime() on the backend rejects anything else.
inline bool formatIso8601Utc(int64_t epochSeconds, char *out, size_t outLen) {
  if (out == NULL || outLen < 21) return false;
  time_t t = (time_t)epochSeconds;
  struct tm utc;
  if (gmtime_r(&t, &utc) == NULL) return false;
  return strftime(out, outLen, "%Y-%m-%dT%H:%M:%SZ", &utc) == 20;
}

// Serializes the ReadingPayload contract. Returns the body length, or 0 if the
// payload could not be produced.
//
// The numbers are pre-formatted with snprintf and inserted as raw JSON rather
// than handed to ArduinoJson as floats: the signature is computed over these
// exact bytes, so the output has to be byte-identical every time and must not
// depend on the library's float-rendering choices.
//
// humidity is always null - the BMP280 has no humidity sensor - as are the
// wind and precipitation fields, which have no hardware at all yet.
inline size_t buildReadingBody(const char *isoTimestamp, float temperature,
                               float pressure, char *out, size_t outLen) {
  if (!isfinite(temperature) || !isfinite(pressure)) return 0;

  char temperatureText[16];
  char pressureText[16];
  snprintf(temperatureText, sizeof(temperatureText), "%.2f", temperature);
  snprintf(pressureText, sizeof(pressureText), "%.2f", pressure);

  JsonDocument doc;
  doc["timestamp"] = isoTimestamp;
  doc["temperature"] = serialized(temperatureText);
  doc["humidity"] = nullptr;
  doc["pressure"] = serialized(pressureText);
  doc["windSpeed"] = nullptr;
  doc["windDirection"] = nullptr;
  doc["precipitation"] = nullptr;

  if (measureJson(doc) + 1 > outLen) return 0;
  return serializeJson(doc, out, outLen);
}
```

```cpp
// Lowercase-hex HMAC-SHA256 over "<timestampMs>.<body>", keyed with the device
// secret as raw text. This mirrors apps/web/src/lib/ingest/verify-signature.ts
// exactly; the 64-character hex secret is the key as-is, never hex-decoded.
// outLen must be at least 65 (64 hex characters plus the terminator).
inline bool signPayload(const char *secret, const char *timestampMs,
                        const char *body, char *outHex, size_t outLen) {
  if (secret == NULL || timestampMs == NULL || body == NULL) return false;
  if (outHex == NULL || outLen < 65) return false;

  const size_t secretLen = strlen(secret);
  SHA256 hash;
  hash.resetHMAC(secret, secretLen);
  hash.update(timestampMs, strlen(timestampMs));
  hash.update(".", 1);
  hash.update(body, strlen(body));

  uint8_t digest[32];
  hash.finalizeHMAC(secret, secretLen, digest, sizeof(digest));

  static const char HEX[] = "0123456789abcdef";
  for (size_t i = 0; i < sizeof(digest); i++) {
    outHex[i * 2] = HEX[digest[i] >> 4];
    outHex[i * 2 + 1] = HEX[digest[i] & 0x0f];
  }
  outHex[64] = '\0';
  return true;
}

// HTTPClient reports transport-level failures as negative codes. Those and 5xx
// are worth another attempt; a 4xx will be rejected identically every time, so
// retrying it just spends the reading's remaining attempts for nothing.
inline bool shouldRetryUpload(int httpCode) {
  if (httpCode <= 0) return true;
  return httpCode >= 500 && httpCode <= 599;
}
```

```cpp
static void dropPendingUpload(const char *reason) {
  Serial.printf("Reading dropped: %s\n", reason);
  uploadPending = false;
  uploadAttempt = 0;
}

static void scheduleRetryOrDrop(const char *reason) {
  if (uploadAttempt >= UPLOAD_MAX_ATTEMPTS) {
    dropPendingUpload(reason);
    return;
  }
  retryDelayMs = UPLOAD_RETRY_DELAYS_MS[uploadAttempt - 1];
  Serial.printf("Upload failed (%s), attempt %u of %u in %u ms\n", reason,
                uploadAttempt + 1, UPLOAD_MAX_ATTEMPTS, retryDelayMs);
}

// Closes the sampling window: takes the mean, stamps it, builds and signs the
// body. The signed tuple is kept for the retries so every attempt sends an
// identical request - the server dedups on (device_id, timestamp), so a retry
// that actually did arrive the first time is a harmless no-op.
static void closeUploadWindow() {
  windowStart = millis();

  float meanTemperature = 0.0f;
  float meanPressure = 0.0f;
  bool haveMean = accumulatorMean(windowSamples, meanTemperature, meanPressure);
  accumulatorReset(windowSamples);

  if (!haveMean) {
    Serial.println("Window closed with no valid samples, nothing to upload");
    return;
  }
  if (!ensureClock()) {
    Serial.println("Window closed before the clock synced, dropping the reading");
    return;
  }
  if (uploadPending) {
    dropPendingUpload("superseded by a newer reading");
  }

  struct timeval now;
  gettimeofday(&now, NULL);
  int64_t epochMs = (int64_t)now.tv_sec * 1000 + now.tv_usec / 1000;
  snprintf(pendingTimestampMs, sizeof(pendingTimestampMs), "%lld", (long long)epochMs);

  char iso[24];
  if (!formatIso8601Utc(now.tv_sec, iso, sizeof(iso))) {
    Serial.println("Could not format the timestamp, dropping the reading");
    return;
  }
  if (buildReadingBody(iso, meanTemperature, meanPressure, pendingBody,
                       sizeof(pendingBody)) == 0) {
    Serial.println("Could not build the payload, dropping the reading");
    return;
  }
  if (!signPayload(DEVICE_SECRET, pendingTimestampMs, pendingBody,
                   pendingSignature, sizeof(pendingSignature))) {
    Serial.println("Could not sign the payload, dropping the reading");
    return;
  }

  uploadPending = true;
  uploadAttempt = 0;
  retryDelayMs = 0;
  Serial.printf("Reading ready: %s\n", pendingBody);
}

static void attemptUpload() {
  uploadAttempt++;
  lastAttemptAt = millis();

  WiFiClientSecure client;
  client.setCACert(ISRG_ROOT_X1_PEM);
  HTTPClient http;
  http.setTimeout(UPLOAD_TIMEOUT_MS);

  if (!http.begin(client, apiUrl)) {
    scheduleRetryOrDrop("cannot open the connection");
    return;
  }
  http.addHeader("content-type", "application/json");
  http.addHeader("x-device-id", DEVICE_ID);
  http.addHeader("x-timestamp", pendingTimestampMs);
  http.addHeader("x-signature", pendingSignature);

  int code = http.POST((uint8_t *)pendingBody, strlen(pendingBody));

  if (code >= 200 && code < 300) {
    http.end();
    Serial.printf("Reading uploaded (%d)\n", code);
    uploadPending = false;
    uploadAttempt = 0;
    return;
  }

  String response = code > 0 ? http.getString() : http.errorToString(code);
  http.end();
  Serial.printf("Upload attempt %u returned %d: %s\n", uploadAttempt, code,
                response.c_str());

  if (!shouldRetryUpload(code)) {
    if (code == 401) {
      dropPendingUpload("401 - check DEVICE_SECRET and the clock");
    } else {
      dropPendingUpload("rejected by the server, retrying cannot help");
    }
    return;
  }
  scheduleRetryOrDrop("transient failure");
}
```

- [ ] **Step 1: Add the section**

Add a "Uploading readings" section after the existing WiFi setup section:

````markdown
## Uploading readings

Once the device is connected and the clock is synced over NTP, it averages the
2-second BMP280 samples over each `SEND_INTERVAL_MS` window (default 300000,
five minutes) and POSTs the mean to the backend.

The payload is signed the way the ingest route verifies it — HMAC-SHA256 over
`<x-timestamp>.<body>`, keyed with `DEVICE_SECRET` used as text, sent as
lowercase hex in `x-signature` alongside `x-device-id`.

```json
{"timestamp":"2026-08-04T12:00:00Z","temperature":21.53,"humidity":null,
 "pressure":1013.24,"windSpeed":null,"windDirection":null,"precipitation":null}
```

`humidity` is always null: the BMP280 measures temperature and pressure only.
Wind and precipitation are null because there is no hardware for them yet.
Pressure is the measured station pressure, not normalized to sea level.

### Delivery policy

| Outcome | Behavior |
| --- | --- |
| 2xx | Success |
| Network error, timeout, 5xx | Retried — 3 attempts in total, spaced 10 s then 30 s |
| 401 | Dropped immediately; check `DEVICE_SECRET` and the clock |
| 400 | Dropped immediately; the payload was rejected as malformed |
| WiFi lost | Reading dropped, the device returns to the reconnect backoff without rebooting |

A reading that cannot be delivered in 3 attempts is dropped. There is no local
buffering — that is a deliberate MVP decision (PRD OQ2), not an oversight.

### TLS

Uploads verify the server certificate against ISRG Root X1, the Let's Encrypt
trust anchor Vercel issues under, embedded in `src/ca_isrg_root_x1.h`. There is
no plaintext fallback. Verification needs a correct clock, so uploads are held
until NTP succeeds; a failed sync is retried on later windows.

(The OTA path is different on purpose: it uses `setInsecure()` because image
authenticity comes from the Ed25519 signature over the version and digest, not
from TLS.)

### Changing the endpoint

The URL comes from NVS, falling back to the flash-time `API_URL` build flag when
NVS is empty. To repoint a device without reflashing, open the web portal at the
device's LAN IP (printed to serial on connect), go to **Setup**, and set
**Backend URL**. Only `https://` URLs are accepted. The active URL is printed at
boot and whenever it changes.
````

  `test/` for the host. `main.cpp` is never part of the native build, which is
  why every decision worth testing lives in `lib/`.
- Clang/IDE diagnostics on the firmware files (`unity.h` not found, unknown
  Arduino types) are a clangd include-path artifact, not real errors. Trust
  `pio`, not the editor squiggles.
- The house style in `lib/` is header-only `inline` functions, plain C strings
  and structs, no Arduino types — that is what makes the native tests possible.
